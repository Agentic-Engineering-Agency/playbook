# Security policy

Security support covers the current `main` branch and the production site at <https://labs.agenticengineering.agency>. Historical revisions, local modifications, linked third-party tools, and linked product repositories follow their own maintenance and security policies.

## Report a vulnerability privately

Use [GitHub private vulnerability reporting](https://github.com/Agentic-Engineering-Agency/playbook/security/advisories/new) for vulnerabilities in this repository or its deployed site.

Include:

- the affected route, file, or component;
- the impact and conditions required to reproduce it;
- minimal reproduction steps or a proof of concept;
- any suggested mitigation;
- whether the report contains sensitive data that should receive extra handling.

Do not open a public issue for an unpatched vulnerability, exposed credential, private customer information, or instructions that materially increase exploitability.

## Public documentation problems

Incorrect prose, broken links, stale package status, locale mismatches, and non-sensitive accessibility or rendering defects belong in the [public issue tracker](https://github.com/Agentic-Engineering-Agency/playbook/issues). Product-specific vulnerabilities should be reported to the linked product repository rather than to the Playbook catalog.

The project does not publish a guaranteed response or remediation timeline. Reports are assessed according to reproducibility, impact, and the ownership boundary above.
