---
title: Evidencia
description: Las reglas de evidencia y etiquetado usadas cuando Agentic Engineering publica documentación pública de proyectos.
---

Evidencia en este Playbook significa que una afirmación pública tiene una fuente inspeccionable. No significa que todos los repositorios públicos estén listos para producción ni que su estado actual haya sido certificado de manera independiente.

## Qué publicamos

| Etiqueta pública | Evidencia requerida |
| --- | --- |
| Propiedad de la organización | GitHub reporta `Agentic-Engineering-Agency` como propietario y el repositorio no es un fork. |
| Código abierto | El repositorio o paquete distribuido declara una licencia reconocida; la tarjeta identifica qué superficie la contiene. |
| Código público | El código es visible, pero no se implica una licencia abierta para todo el repositorio. |
| Paquete público | El paquete indicado resuelve en el registro público al momento de la revisión. |
| Documentación pública | El enlace apunta a documentación canónica propiedad del proyecto o de la organización. |

## Qué se omite intencionalmente

- salud interna de proyectos, roadmaps, clientes, métricas operativas o datos de fundadores
- benchmarks o afirmaciones de producción sin una revisión separada de evidencia
- comandos de instalación que no resuelven en el registro o manifest indicado
- forks presentados como proyectos propiedad de Agentic Engineering
- experimentos archivados presentados como entradas actuales del catálogo

<Callout type="info">
Los datos del catálogo son una fotografía editorial fechada. Antes de cambiar un estado, licencia, paquete o ruta de instalación, vuelve a revisar su fuente pública canónica.
</Callout>

El estado de licencia del propio repositorio del Playbook se documenta en [Acerca de este Playbook](/es/docs/about#licencia-del-repositorio).
